设计稿交付开发前，哪些元素需要切图？

不是设计稿上的所有内容都应该变成图片。把固定视觉交给资源、把可变化内容交给代码，才是稳定的 UI 交接方式。

一句话判断规则

如果元素会随数据、语言、状态或屏幕尺寸变化，优先交给代码；如果它是固定视觉且需要保留细节，再导出图片。

建议优先切出的四类元素

元素适合切图的原因交付提示
品牌与复杂图形Logo、纹理、手绘插画、3D 视觉通常难以用 CSS 稳定复现。注明比例、背景和深浅色版本。
固定图标图标外观固定，且需要保留透明边缘与阴影细节。同组图标统一画布和命名。
活动与业务视觉角标、徽章、海报和商品图属于内容资产。按页面、活动或状态分组。
截图中可复用的插画源文件缺失时，截图可能是唯一可用线索。保留人工校对，避免带入邻近文字。

通常不应切图的内容

标题、正文、价格、表单字段、普通按钮文案、分割线和标准圆角容器，通常应由 HTML、CSS 或组件实现。它们需要适应不同屏幕、语言长度、数据状态和无障碍阅读；做成图片会让搜索、适配和维护都变得更困难。

交付前检查清单

  1. 每个资源是否有清晰用途、页面位置和状态说明？
  2. 同一组图标是否拥有一致的画布尺寸、留白和命名？
  3. 是否误把可编辑文字、价格或业务数据做成了图片？
  4. 是否提供了实际展示尺寸、倍率和是否允许拉伸的说明？
  5. 开发能否在 30 秒内找到需要的文件，而不必重新询问设计师？

常见问题

什么情况下一个元素应该切成图片？

固定视觉、复杂细节且不随数据或语言变化的元素，通常适合切图。

标题和按钮文案要不要切图？

通常不要，应由代码实现以支持响应式、搜索和无障碍。

图片交付还需要哪些说明？

至少说明文件名、用途、状态、画布尺寸、展示尺寸和是否允许拉伸。
